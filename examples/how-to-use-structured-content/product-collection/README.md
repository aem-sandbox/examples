# Structured Content: a product collection

A third schema on the same `da-sc` delivery worker as the [product catalog](../README.md) and
[promotion](../promo). This one is an editorial layer over data this site doesn't own: the record
holds curation (a name, description, and an ordered list of SKUs) rather than facts, and the
facts are resolved from [`/products/product-detail/query-index.json`](../../how-to-use-json2html)
at render time by [`blocks/product-collection`](../../../blocks/product-collection).

The SKUs in `delivery-response.json` reference `product-detail` pages generated by JSON2HTML —
see [`how-to-use-json2html`](../../how-to-use-json2html) for that side of the pipeline.

## What is here

| File | What it is |
| --- | --- |
| [`product-collection.schema.json`](product-collection.schema.json) | The `Product Collection` schema. |
| [`delivery-response.json`](delivery-response.json) | A live response from the `da-sc` worker, for the `summer-essentials` record. |

Neither is loaded by the site. Reference copies only, same as the product and promotion examples.

## Gotcha

The collection never authors product facts, only SKUs. A SKU with no matching row in the query
index (removed, renamed, unpublished) is silently dropped from the rendered grid — the block has
no "missing product" state, because from its perspective a SKU it can't resolve never existed.
